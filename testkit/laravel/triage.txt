#
# Every DIFFERENCE between a Ferro column and its stock-pdo control must be explained here, by an
# entry whose EXPECTATION matches what Ferro actually did — the failure type and message, or the skip.
# The laravel-suite workflow runs testkit/dbal/compare-columns.php --triage on every Ferro column and
# FAILS on a difference no entry matches; ci/check-suite-triage.sh checks every entry and citation on
# every push. The format is documented at the top of compare-columns.php. Upstream paths are relative
# to the pinned laravel/framework v11.51.0 clone, and each upstream:/upstream-class:/upstream-via: line is re-checked
# against it on every suite run — including that it is a gate on the entry's OWN class or method.
#
# Column keys: laravel-<server>-<driver>, and laravel-<server>-specific-<driver> for upstream's
# family-specific directory (which runs under the stock name only):
#   laravel-pg-ferro-pgsql        laravel-pg-pgsql        laravel-pg-specific-pgsql
#   laravel-mysql-ferro-mysql     laravel-mysql-mysql     laravel-mysql-specific-mysql
#   laravel-mariadb-ferro-mariadb laravel-mariadb-mariadb laravel-mariadb-specific-mariadb
#   laravel-sqlite-ferro-sqlite   laravel-sqlite-sqlite
#
# WHERE THE EXPECTATIONS COME FROM. The entries were collected from the recorded triage —
# docs/laravel-suite/2026-09-10-c2-results.md (C2/C2e), 2026-09-15-c3-6b-sqlite-results.md (C3-6b),
# 2026-10-02-c1f-mysql-results.md, 2026-10-02-c1g-results.md and SPEC §22.3 — and every expectation was
# then DERIVED from the dev container's JUnit, each Ferro column beside its control: PostgreSQL 16.13,

# MySQL-only entries are marked UNVERIFIED. A wrong expectation fails closed: the gate prints what
# Ferro actually did, never green.
