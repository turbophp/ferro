# testkit/dbal/triage.txt — the D18 triage of the doctrine/dbal subset (SPEC D18; E9, SPEC §22.2 (da)).
#
# SPEC D18 calls a suite column green when it has parity with a stock-driver control and every
# Ferro-only non-pass is either upstream code branching on the driver NAME or an incompatibility
# documented in docs/known-incompatibilities.md. This file is that list for testkit/dbal-suite.sh.
# testkit/dbal/compare-columns.php --triage reads it after each Ferro column runs beside its control,
# and FAILS the dbal-suite workflow on a Ferro-only non-pass that no entry here covers.
# ci/check-suite-triage.sh checks every citation on every push. The format is documented at the top
# of compare-columns.php.
#
# Column keys: dbal<major>-<family> — dbal4-pg, dbal4-mysql, dbal4-mariadb, dbal4-sqlite, and the
# same with dbal3 (the runner's two pinned trees, 4.4.4 and 3.10.6).
#
# SEEDED BY COLLECTION, NOT RE-DERIVATION: every entry is a non-pass the recorded triage already
# explained — docs/dbal-suite/2026-08-11-results.md (S8b's categories), 2026-09-09-a5-results.md,
# 2026-09-15-c3-6a-sqlite-results.md and 2026-10-02-c5b-dbal3-results.md — re-measured in the dev
# container against a stock-driver control (PostgreSQL 16, MariaDB 10.11, SQLite) before it was
# written down. Entries the dev container cannot reproduce (MySQL 8.4 is CI-only) come from the
# recorded runner columns and are marked so. A test that fails in the CONTROL too, with the same
# exception type, needs no entry: it is not Ferro's (that does not make it upstream's — C5b's
# PHPUnit-11 method-order artifacts are the harness's).
#

# omission: the replacement TestUtil answers isDriverOneOf() FALSE in BOTH columns, so upstream's
# vendor gates take the same branch under Ferro and under the control (testkit/dbal/TestUtil.ferro.php).
