**Goal:** Real transactions keyed by a `tx_id` that **pins a pooled connection for the transaction's lifetime, NOT the client socket** (SPEC §4/§7 — what makes Fiber-suspended/multiplexed requests correct). `BEGIN{pool,isolation?,readonly?}` → a global-atomic `tx_id`; tx-scoped `EXEC` (S5's method + an optional `tx_id`) + engine-named `SAVEPOINT`/`RELEASE`/`ROLLBACK_TO` run on that pinned conn; `COMMIT`/`ROLLBACK` end it and release the conn (tainted → pool reset). Two deadline timers (`idle_in_tx`, `max_tx`) → `Retryable{TxDeadline}` with the pin released and **no statement re-dispatch** (rule 3). Unknown/cross-session `tx_id` → `Protocol`. Exactly one `END` on every path (rule 4).

## Architecture — the per-`tx_id` actor

A transaction is a **single task (actor) that owns a `Checkout`** (the pinned pooled conn) for the tx's whole life and serializes commands onto it over an mpsc channel:
```
BEGIN → checkout conn → Checkout::begin_tx_with(tx_id, begin_sql) → spawn actor (MOVES the Checkout in) → register tx_id → reply tx_id
tx-scoped EXEC/SAVEPOINT/COMMIT/ROLLBACK → handler looks up actor by tx_id (owner check) → sends TxCommand+oneshot reply → actor runs it on the pinned conn → replies → handler declares the outcome
COMMIT/ROLLBACK/deadline/session-death → actor ends: commit_tx/rollback_tx (or cancel+rollback), Checkout drops → conn returns to pool, deregister tx_id
```
- **`TxRegistry`** (global, `Arc`, a session-layer citizen — see Seam): `tx_id → TxHandle { owner: SessionId, cmd_tx: mpsc::Sender<TxCommand>, done: <awaitable completion signal / JoinHandle> }`. Lookup verifies `owner == calling SessionId` → else `Protocol` (cross-session and unknown are indistinguishable to the caller by design). `tx_id` from a global `AtomicU64` — **monotonic, never reused, bounded < 2^63** (NOT a full-range/`boot_epoch`-style value). `TxRegistry` also owns the `SessionId` counter (`next_session_id()` over an internal `AtomicU64`).
- **The actor loop shape (MAJOR-2 fix — the naive shape takes two mut borrows of the `Checkout` and will not compile; state it up front):** ONE `tokio::select!` on the task that owns the `Checkout`, arms = `{ cmd_rx.recv(), idle_timer, max_timer, abort_signal }`. Process each command to a decision point per iteration. To run a user statement interruptibly: `tokio::pin!` the `Checkout::query(...)` future and `select!` between **it** and the timers/abort — on a timer/abort arm, fire the OUT-OF-BAND server cancel (below), then **await the pinned future to its (now-erroring) completion — do NOT drop it** — so the conn returns at `ReadyForQuery` before any ROLLBACK. Only ONE task ever touches the conn (the borrow checker enforces no concurrent use).
- **Mid-statement deadline/abort (BLOCKER fix):** dropping a tokio-postgres query future does NOT cancel the running server statement, and a follow-on ROLLBACK on the same `Client` pipelines behind it. So the actor cancels the statement server-side out-of-band: grab a `tokio_postgres::CancelToken` from the `Client` (`Client::cancel_token`, reachable via `PgConn.client` — exposed as a new `Checkout::cancel_handle()` / `PoolBackend`-level cancel that runs `CancelToken::cancel_query(NoTls)` over a SIDE connection, borrowing nothing from the `Checkout`). Sequence on deadline/abort mid-statement: (1) fire the out-of-band cancel; (2) await the pinned query future to its `57014` completion; (3) `rollback_tx()` (or `set_tainted(true)` if rollback also errors) then drop the `Checkout`. Then TOMBSTONE the `tx_id` as `TxDeadline`; the next command for that id → `Retryable{TxDeadline}` (never re-runs the statement).
- **Deadlines:** `idle_in_tx` (reset on every command) + `max_tx` (absolute from BEGIN); defaults in `Config` (`idle_in_tx_ms`, `max_tx_ms`).

## Seam evolution (Task 2 — the load-bearing infra; recipe PINNED by verification)

The S3 handler is ONE shared session-agnostic `Arc` (`run_with_handler(stream, config, epoch, handler)` at mod.rs:202; cleanup at mod.rs:421-422 = `registry.cancel_all()` then `drain_supervisors`). Evolve it EXACTLY thus (lowest-churn per the verification):
- **Factory, do NOT extend `HandlerFn`.** Add `type SessionId = u64;` and `type HandlerFactory = Arc<dyn Fn(SessionId) -> HandlerFn + Send + Sync>`. (Extending `HandlerFn` with a leading `SessionId` arg would force edits to the mod.rs:502 call site and the ~8 scripted closures in `session_rules.rs`/`shutdown.rs`/`handshake.rs`/`peercred.rs` — avoid.)
- **`tx_registry: Arc<TxRegistry>` is a NEW explicit param** on `serve` (serve.rs:48) and `run_with_handler` (mod.rs:202) — NOT a `Config` field (`Config` is `#[derive(Debug,Clone)]` pure data, cloned per-connection at serve.rs:89 and re-minted by `Config::default()`).
- **`SessionId` drawn once** in `run_with_handler` via `tx_registry.next_session_id()`, stored in a local, and used both to build the per-connection handler (`factory(session_id)`) and at cleanup.
- **`abort_session` BEFORE drain (consolidated seam+actor+races finding):** sequence becomes `registry.cancel_all()` → `tx_registry.abort_session(session_id).await` (bounded, mirror `config.drain_deadline`) → `drain_supervisors(..)`. Rationale: `cancel_all()` only fires each request's `CancellationToken`, which a tx-scoped handler blocked on a `oneshot` recv does NOT observe; aborting the actors first drops their reply senders → the in-flight handler's recv returns `Err` → it declares its one terminal → the supervisor delivers the END inside the drain window. `abort_session` must be awaitable+bounded → `TxHandle` carries the actor's `JoinHandle`/completion signal.
- **Keep `Session::run` (mod.rs:189) unchanged** by minting a throwaway `Arc<TxRegistry>` + a trivial factory internally (its default handler creates no txs) — so `common/mod.rs:80` and every pure-session test stay untouched.
- **Full call-site list (Task 2, one change):** `main.rs:33/42`; `ferro-e2e/src/main.rs:57/61`; `common/mod.rs:439-449` (`exec_server`) via a new `spawn_with_factory` helper; `sql::make_handler` (sql.rs:64) → returns a `HandlerFactory` capturing `PoolRegistry` + `Arc<TxRegistry>`; wrap the 6 existing plain-`HandlerFn` test helpers as `Arc::new(move |_sid| handler.clone())`.
- **Forwarding-handler liveness (note):** a tx-scoped handler maps mpsc-send `Err` / oneshot-recv `Err` to a PROMPT declared terminal (`Retryable{TxDeadline}` if the id was tombstoned, else `Protocol`) so a mid-teardown race resolves to exactly one END, never a hang. (Belt-and-suspenders — the supervisor's no-terminal synth already guarantees one END.)
