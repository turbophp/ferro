# Ferro M0 · Slice S7 — PHP sync client runtime (the drop-in surface) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The dependency-free `ferro/client` **runtime** — the surface a PHP app actually uses — issuing real queries and transactions against a live `ferrod` over a Unix socket, hydrating results, mapping the three-branch error taxonomy to exceptions, and surviving a daemon restart via an epoch-aware reconnect loop. Built on the existing `Ferro\Protocol\*` codec (S1/S5/S6). This is where Ferro's "config-only drop-in" promise becomes tangible; the Doctrine/Eloquent tiers (M1) and Fibers (post-M0) sit ON this client.

**Charter constraints (load-bearing):**
- **Rule 7 — the client stays runtime dependency-free.** No required Composer runtime deps (`require` is just `php >= 8.2`). `ext-msgpack`/`ext-sockets` are runtime-DETECTED (already via `PackerFactory`), never required. Transport uses `stream_socket_client` (core), not `ext-sockets`.
- **Rule 3 / §19.3 — never auto-retry an `Indeterminate` write.** The client's resilience loop MAY retry a `Retryable` READ (`retry_reads` default true); it MUST NOT auto-retry an `Indeterminate`/`WriteUnconfirmed` outcome (only a manifest `idempotent:true` licenses that — M3). This is the client half of the engine's defining safety property.
- **Rule 2 — `/proto` is the source of truth.** Error branches/codes, method ids, isolation come from `Generated\Constants`; the TX message classes byte-match the Rust `tx_*` golden vectors. No hand-written protocol numbers.
- **PHPStan level 9 clean on `src`** (the charter gate); PHPUnit green.

## Architecture — `Ferro\Client\*` on the codec, synchronous single-in-flight

M0's client is **synchronous**: one in-flight request per connection (Fibers/multiplexing is the `FIBERS` feature, post-M0 — the client advertises `features=0`). So the request loop is: allocate `request_id` → write one framed request → block-read exactly its one terminal `END` frame → decode `Outcome`. No streaming DATA in M0 (S5 buffers into the terminal), so a terminal read is one frame.

```
Ferro (facade / config)                     — DSN/socket, pool name, options (retry_reads, timeouts)
  Client\Transport                           — stream_socket_client unix:// (primary) / tcp:// (FERRO_ADDR fallback); read-exact/write-all; timeouts
  Client\Session                             — HELLO(features=0, TYPE_REGISTRY_HASH) → HELLO_ACK; cache boot_epoch+pools; hard registry check; request_id alloc (monotonic, u32 wrap); send-request→read-one-terminal; PING/PONG; GOODBYE on close
  Client\Connection (Pool for M0 = 1 conn)   — queryOne/query/scalar/rows/exec(+params,readonly) + transaction(closure, RetryPolicy?)
  Client\Hydration\{HydrationPlan,PlanCache} — cols+rows → arrays OR `final readonly` DTOs (snake→camel), reflection built ONCE per (DTO,column-shape), memoized
  Client\Value policies (§9.1)               — canonical TypedValue → PHP scalar; M0 set is NULL/BOOL/I64/F64/TEXT/BYTES (a skeleton for the DECIMAL/TIMESTAMP/UUID/JSON policies that land in M1)
  Client\Error\{ErrorMapper, exception tree} — Outcome::Error{code,branch} → RetryableException | IndeterminateException | NonRetryableException (branch from the wire byte, code/sqlstate carried)
  Client\ReconnectLoop + FateClassifier      — on ConnectionLost: full-jitter backoff reconnect, compare boot_epoch (changed ⇒ engine state voided: open tx dead), re-verify registry hash; retry a Retryable READ (retry_reads), NEVER an Indeterminate write
```

## Live test harness (the novel dimension — VERIFIED, zero ferrod changes)

PHP live tests need a REAL `ferrod` process (PHP can't spawn the daemon in-process). **D-S7-1 (verified against `main.rs`/`config.rs`):** `ferrod` is configured ENTIRELY by env vars (`Config::from_env`), so the harness needs NO ferrod change — the exact recipe:
```
FERRO_SOCK=<scratch>/ferro-test-<pid>.sock \
FERRO_POOLS=default \
FERRO_POOL_DEFAULT_DSN=$FERRO_TEST_PG_URL \
  <ferrod-binary>            # launched as a background process
```
`FERRO_SOCK` sets the UDS listen path (default `/run/ferro/dev.sock`); `FERRO_POOLS`=comma-separated names; `FERRO_POOL_<NAME>_DSN` (NAME uppercased/sanitized → `FERRO_POOL_DEFAULT_DSN`) carries the DSN. The `SO_PEERCRED` gate is **self-only** by default (empty `FERRO_ALLOW_UIDS` ⇒ only the daemon's own uid) — which PASSES because PHPUnit launches `ferrod` as the SAME uid as the PHP client. A base `tests/Live/LiveTestCase.php` (active only when `FERRO_TEST_PG_URL` is set AND a `ferrod` binary is available — else the test SKIPs, so `composer test` stays green offline): build once via `cargo build -p ferrod` (binary at `engine/target/debug/ferrod`, or accept `FERRO_FERROD_BIN`). **Setup hardening (each point is a real failure mode from verification):**
- **Socket path under `sys_get_temp_dir()`** → `/tmp/ferro-test-<pid>.sock`, NOT the deep nested session scratch dir: `sockaddr_un.sun_path` is 108 bytes, and a long scratch path overflows it so `UnixListener::bind` fails and `ferrod` exits at startup while a naive poll just times out with no diagnosis. **Assert `strlen($socketPath) < 104` before launch.**
- Assert `FERRO_TEST_PG_URL` is set + non-empty BEFORE launch (an empty DSN → `parse_pools` skips it → an empty registry that PASSES HELLO but fails every EXEC with `Unsupported: unknown pool`).
- Spawn via `proc_open` with stderr redirected to a file; bound readiness with a ~5 s deadline; on each poll iteration check the child is still alive (`proc_get_status()['running']`) and **fail fast with the captured stderr** if it exited; make the readiness probe a FULL HELLO + `SELECT 1` round-trip (not a bare socket connect — that would pass even with an empty registry).
- **Teardown (on success AND failure):** SIGTERM + wait, then **unlink the socket file** (`ferrod` does not unlink on graceful shutdown — it only stale-unlinks at the next bind), with a **SIGKILL fallback** if the child hasn't exited within ~6 s (`drain_deadline` 5 s + margin) so a wedged upstream can't hang the suite.
Document the one-command live run.

Add a decoder mirroring `ExecOk.mapFromWire`: `Outcome` = `[status, body]`; `ErrorPayload` = the positional `array(7)` `[code, branch, sqlstate, errno, message, detail, retry_after_ms]` (the `branch` byte is `ErrorPayload[1]` — this is what `ErrorMapper` classifies on). The `Outcome::Ok(ExecOk)` / `Outcome::Cancelled` arms compose with the existing decoders.
- [ ] Extend `VectorConformanceTest` (data-driven — it already iterates `proto/vectors/`) so the `tx_begin_request`/`tx_begin_response`/`tx_commit`/`tx_savepoint` vectors AND **`error_protocol.json`** (the `Outcome::Error` wire) byte-match BOTH directions (encode==bytes + decode==value), exactly as `sql_exec_*` does. This makes PHP an independent arbiter for the TX wire AND the error wire, closing the S6 boundary and grounding the Task-3 taxonomy in a real vector.

### Task 2: transport + session/handshake + the live harness
- [ ] `Client\Transport` (`stream_socket_client`, unix:// primary / tcp:// fallback; blocking read-exact of the 16-byte header then `payload_len` bytes; write-all; connect+read timeouts; a clean `close`). Dependency-free (no `ext-sockets`). Implementer note (not an L9 defect): a stream resource has no native property type → hold it as `/** @var resource */ private $sock` (the class is not `readonly`); handle `stream_socket_client`'s `resource|false` + `fread`'s `string|false` returns explicitly for L9.
- [ ] `Client\Session`: HELLO (`client_version`, `TYPE_REGISTRY_HASH`, `manifest_hash=null`, `pid=getmypid()`, `features=0`), then read ONE reply frame and **branch on it (the registry check is SERVER-side — a client-side hash compare can never fire)**: a `CORE/HELLO_ACK` frame (flags=0, NOT END) → decode `HelloAck`, cache `boot_epoch` + `pools`; an **`Outcome::Error` terminal on `request_id=0` with `flags::END`** (`service=CORE, method=0` — the shape the daemon emits when `validate_hello` rejects a registry/version mismatch, `error.rs` `terminal_frame(0,ep)`) → decode `ErrorPayload` and throw a distinct FATAL exception keyed on `code == errc::UNSUPPORTED` (from `Generated\Constants`). Do NOT assert the reply's `request_id` equals the HELLO id, and do NOT hard-fail by comparing hashes client-side. **`boot_epoch` is stored as an OPAQUE scalar `int|string`** exactly as `PurePacker` yields it (a `u64 > PHP_INT_MAX` decodes to a DECIMAL STRING via `be64ToDec`; `boot_epoch` is a random full-range u64 so this happens ~50% of the time) — never `(int)`-coerced (coercion collapses distinct large epochs to `PHP_INT_MAX`, defeating epoch-change detection). `request_id` allocator: monotonic `u32`, wraps, never 0 (0 is reserved for session terminals). `sendRequest(service,method,payload) -> Outcome`: write one frame, block-read one terminal — **assert `flags::END` + the echoed id ONLY for a request-bearing SQL/TX terminal**; a terminal on `request_id=0` with `END` is a SESSION-FATAL signal → route it into the ConnectionLost/reconnect+fate path (Task 4), decoding its `Outcome::Error` for code/branch (NOT a generic id-mismatch `ProtocolException`, which would mask a real session-fatal). `ping()` reads a `PONG` (flags=0, NOT END — a distinct read path, assert method+id not END); `close()` sends GOODBYE.
- [ ] The **live harness** (D-S7-1): `tests/Live/LiveTestCase.php` managing the `ferrod` process (env recipe above). A first live test `handshake_returns_boot_epoch_and_pools`: connect, HELLO, assert HELLO_ACK carries a `boot_epoch` field AND that TWO connects in one run report the SAME epoch (a running instance draws it once — `nonzero` is nondeterministic + int-typed, don't assert that), and assert `pools == ['default']`.
- [ ] **WIRE `HelloAck.pools` (close the S6 tracker — verified ~3 lines, NO seam change).** The false "thread the registry through the seam" rationale is wrong: pool NAMES already live in `config.pools` (`PoolSpec.name`), and `Config` is already in scope at the single `hello_ack_frame` call site (`session/mod.rs:326`). Add a `pool_names: Vec<String>` param to `hello_ack_frame` (`handshake.rs:44`) and pass `config.pools.iter().map(|p| p.name.clone()).collect()` at the call site. Zero signature/test-helper churn beyond that one call. (This is a small Rust change in S7; regen/PHP unaffected.)
- **Gate:** unit (handshake hard-fail on hash mismatch via a fake transport; request_id monotonic+wrap; a frame round-trip over an in-memory transport) + the live handshake test; `phpstan L9`. **Commit** `feat(s7): PHP transport + Session handshake (epoch/registry check, request_id, one-terminal read) + live harness`.

### Task 3: query API + hydration + error mapping + value policies
- [ ] `Client\Error`: an exception hierarchy `FerroException` → `RetryableException` / `IndeterminateException` / `NonRetryableException` (+ a `ProtocolException`), each carrying `code`/`branch`/`sqlstate`/`message`. `ErrorMapper::fromOutcomeError(ErrorPayload)` picks the class **from the wire `branch` byte** (`Generated\Constants` branch values: 1 Retryable, 2 Indeterminate, 3 NonRetryable) — never from the code, so an unknown code still classifies. **A branch byte NOT in {1,2,3} MUST map to NonRetryable (a `ProtocolException`), never a default that could be retried** — defaulting an unknown/garbled branch to retryable would breach the never-retry property (unit case required). `Outcome::Cancelled` → a `CancelledException` (NonRetryable-ish).
- [ ] `Client\Connection` query API — **reads declare `readonly=TRUE`, only `exec()` (+ tx-scoped writes) default `readonly=false` (§19.3-CRITICAL):** `exec(sql, params=[], readonly=false)`, `query(sql,params)` / `queryOne(sql,params)` / `scalar(sql,params)` / `rows(sql,params)` all build `ExecRequest` with **`readonly=true`**. The engine gates the Indeterminate split on the client-declared `readonly` flag ALONE (no SQL inference — `sql.rs pool_error_to_payload`: `sent && !readonly → WriteUnconfirmed{Indeterminate}`), so a SELECT sent with `readonly=false` whose conn dies mid-flight would be surfaced as `Indeterminate` (which the client never retries) — WRONG for a read (a read has no write-fate; it should be `Retryable{ConnectionLost}`) and it would leave the Task-4 daemon-restart gate with no retryable op. Each builds an `ExecRequest` (`tx_id=null`, `fetch` per shape), `sendRequest`, and on `Outcome::Error` throws the mapped exception; on `Ok` decodes `ExecOk` and hydrates.
- [ ] `Client\Hydration\{HydrationPlan, PlanCache}`: cols+rows → `array` (assoc, column name → PHP value) by default; `queryOne(..., DtoClass::class)` / `query(..., DtoClass::class)` hydrate into `final readonly` DTOs (constructor-promoted props; snake_case column → camelCase param). The reflection plan (param order, name map) is built ONCE per (DTO, column-name-tuple) and memoized in `PlanCache` — a unit test proves ONE reflection build across N hydrations of the same shape.
- [ ] `Client\Value` policies (§9.1, M0 skeleton): canonical `Value` → PHP (`NULL`→null, `BOOL`→bool, `I64`→int [note: > PHP_INT_MAX is post-M0/unreachable in the scalar tests], `F64`→float, `TEXT`→string, `BYTES`→string). A documented extension point for the M1 DECIMAL/TIMESTAMP/UUID/JSON policies (`naive_datetime_zone=utc`, safe-object defaults) — not implemented in M0 (those tags are `Unsupported`).
- **Gate:** unit (ErrorMapper branch mapping incl. unknown code; HydrationPlan memoization = one reflection build per shape; value-policy table; queryOne-null) + live (`scalar('SELECT 1') === 1`; `query('SELECT 1 AS n, ...')` → assoc rows; `queryOne` into a `final readonly` DTO; a syntax error → `NonRetryableException{Syntax}`); `phpstan L9`. **Commit** `feat(s7): PHP query API + memoized DTO hydration + three-branch error mapping + M0 value policies`.

### Task 4: transaction(closure) + reconnect loop + fate classifier + retry policy
- [ ] `Ferro`/`Connection::transaction(callable $fn, ?RetryPolicy $policy = null)`: `BEGIN{pool,isolation?,readonly?}` → `tx_id`; call `$fn($tx)` where `$tx` is a tx-scoped handle whose `exec`/`query` carry the `tx_id` (tx-scoped `ExecRequest`); on normal return → `COMMIT`; on a thrown exception → `ROLLBACK` (best-effort) then rethrow. SAVEPOINT/RELEASE/ROLLBACK_TO exposed for nested use if cheap, else deferred with a note.
- [ ] **Lost-COMMIT carve-out (§19.3-CRITICAL).** In the sync single-in-flight model the client knows the last in-flight frame's `(service, method)`. A no-response/`ConnectionLost` whose last in-flight frame was `SERVICE_TX / METHOD_TX_COMMIT` MUST be classified **`Indeterminate`** and the closure/RetryPolicy MUST NOT re-run it (an already-committed tx could be re-applied). The RetryPolicy may re-run the closure ONLY when the lost op was a mid-tx STATEMENT (the tx is provably dead — BEGIN never returned, or a statement/`epoch_changed` voided an open `tx_id`), never for a lost COMMIT. Unit test: a lost COMMIT is never retried.
- [ ] `Client\ReconnectLoop` + `FateClassifier`: on a `ConnectionLost`/transport failure, reconnect with **full-jitter exponential backoff** (bounded attempts), then compare the new `boot_epoch` to the cached one **as an OPAQUE scalar with strict equality (`===`), NO `(int)` coercion** (it may be a decimal STRING for values > PHP_INT_MAX; coercion collapses distinct large epochs to `PHP_INT_MAX` → a real restart would compare EQUAL → the dead `tx_id` never voided, a §19.1/§19.3 violation) — **changed ⇒ all engine-side state (any open `tx_id`) is void**, surface it (a reconnect exception carrying `epoch_changed:true`) — and re-verify the registry (the server enforces it, see Task 2). **`retry_reads` (default true):** on a `RetryableException` for a READ (`readonly=true` op), the loop MAY transparently re-issue after reconnect; on an `IndeterminateException` (or any write, or a lost COMMIT), it MUST NOT — it propagates (the client never converts an Indeterminate into a silent retry). `FateClassifier` decides retry-eligibility from (branch, readonly, op-kind, idempotent?) — `idempotent` is always false in M0 (manifests are M3).
- **Gate:** unit (backoff bounded + jittered; **epoch-compare with TWO distinct `> PHP_INT_MAX` decimal-string epochs asserts UNEQUAL** and voids state; `FateClassifier` NEVER retries Indeterminate, NEVER retries a lost COMMIT, retries a Retryable read, does not retry a Retryable write unless idempotent; RetryPolicy honored) + live (`transaction` commit persists / a thrown exception rolls back — verified by a fresh autocommit SELECT; **daemon restart mid-session** → the next call sees a changed `boot_epoch` and surfaces `epoch_changed:true`, and a subsequent readonly call retries and succeeds against the restarted daemon); `phpstan L9`. **Commit** `feat(s7): PHP transaction(closure) + epoch-aware reconnect loop + FateClassifier (retry reads, never Indeterminate/lost-COMMIT)`.
