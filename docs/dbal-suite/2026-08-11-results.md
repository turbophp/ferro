### Reproducibility — verified, on all three backends

Every backend was run **twice** with the identical command, and both the PHPUnit result line **and
the full ordered list of non-passing tests** were diffed. All six comparisons produced no
differences.

| backend | run 1 | run 2 | result line | failure set |
|---|---|---|---|---|
| PostgreSQL | `Tests: 730, Assertions: 664, Errors: 71, Failures: 7, Skipped: 354, Incomplete: 2` | identical | same | same |
| MySQL | `Tests: 730, Assertions: 869, Errors: 4, Failures: 9, Skipped: 341, Incomplete: 4` | identical | same | same |
| MariaDB | `Tests: 730, Assertions: 867, Errors: 4, Failures: 9, Skipped: 342, Incomplete: 4` | identical | same | same |

**The reset is what buys that, and the cost of dropping it is measured.** Same command, same code,
PostgreSQL, only the `--no-reset` flag changing:

| | assertions | errors | failures |
|---|---|---|---|
| with the reset (twice, identical) | 664 | **71** | 7 |
| without the reset (twice, identical) | 623 | **85** | 7 |

The 14 extra errors are all leftover state — `testCreateSequence`, `testListSequences`,
`testTableInNamespace`, `testSupportDomainTypeFallback`,
`testListTableDetailsWhenCurrentSchemaNameQuoted` and nine more, every one in `Schema\PostgreSQL*`.

Two notes about how the reset got to this state, because both are the kind of thing that quietly
rots:

1. The plan's draft `reset-pg.sql` dropped a **hand-written list** of schemas
   (`testschema`, `nested`, `another`). The first measured runs then drifted **71 → 72 errors**
   between a virgin database and every run after it, because `Schema/SchemaManagerFunctionalTestCase`
   also leaves `001_test` and `test_create_schema` behind. `reset-pg.sql` now enumerates from
   `pg_namespace` and drops every non-system schema; a list cannot rot if there is no list.
2. The plan predicted that two consecutive `--no-reset` runs would **differ**, the second being
   worse. Measured, they do not: the residue **saturates after one run**, because the upstream
   suite's own `dropAndCreateTable()` re-establishes most of its objects and what survives is a fixed
   set. The falsifiable property is the with-vs-without comparison above, not a run-over-run drift,
   and that is what is recorded here.

## The bar, restated — and what of it is unmeetable

SPEC §14 states the acceptance bar as *"DBAL 4 functional test suite green on PG + MySQL + SQLite;
ORM functional suite green on PG + MySQL"*. Five measured facts make that unreachable as written.
They are stated rather than quietly narrowed away:

1. **SQLite is impossible.** `engine/crates` has `pg` + `mysql` only (`AnyPool { Pg | Mysql }`).
   One third of the DBAL bar waits for `ferro-backend-sqlite`.
2. **The ORM suite is not run at all.** `doctrine/orm` is not a dependency of this repository and its
   harness has the same driver-injection problem. Deferred, with the ORM+PostgreSQL+IDENTITY blocker
   documented in `docs/known-incompatibilities.md` (controller decision D-S8b-5).
3. **The upstream suite cannot select a third-party `driverClass`.** `TestUtil::getConnectionParams()`
   honours only `$params['driver']` and otherwise returns `['driver' => 'pdo_sqlite', 'memory' => true]`.
   This was reproduced deliberately during this slice: with the contact assertion disarmed and
   upstream's `TestUtil` restored, `DataAccessTest` reported **`OK (105 tests, 211 assertions)`
   against in-memory SQLite 3.45.1 with zero Ferro contact**, nothing skipped. Neither
   `--fail-on-skipped` nor `ci/assert-no-skips.sh` can see that. `testkit/dbal/TestUtil.ferro.php`
   plus the bootstrap's contact assertion are what close it.
4. **Even the stock drivers are not green on these containers.** Recorded before this slice:
   `pdo_pgsql` over the whole `tests/` tree was `Tests 3913, Failures 1, Skipped 556, Incomplete 4`,
   and `pdo_mysql` over `tests/Functional` was `Tests 1077, Errors 1057` — every test erroring in
   `TestUtil::initializeDatabase()` with `1044 Access denied … to database 'doctrine_tests'`.
5. **A subset, not the whole tree.** `testkit/dbal/allowlist.txt` selects 11 `tests/Functional`
   paths and records a reason for every exclusion.

**The bar this slice actually measured**, and the one a later slice should measure against:
*the curated subset in `testkit/dbal/allowlist.txt`, run through the real `DriverManager` against a
real backend with driver identity asserted, green modulo the triaged list below.*

| backend | tests | executed | passed | assertions | failures | errors | skipped | incomplete | time |
|---|---|---|---|---|---|---|---|---|---|

### The skipped count — CORRECTED, this file's original explanation was measurably false

The original text here said the large `skipped` count was `TestUtil::isDriverOneOf()` answering
false for every driver name, "a deliberate choice with 60 upstream call sites behind it". Measured
with `--display-skipped` and the reasons aggregated, on all three backends:

```
    299 Skipping since connected to Doctrine\DBAL\Platforms\<Platform>
     13 This test requires MySQL or MariaDB.        7 Test works only on MySQL.
      2 The platform supports sequences.            1 This test only works on MySQL/MariaDB.
      … (the remainder are one-off platform-capability gates)
```

**299 of the 354 / 341 / 342 skips come from one place:**
`Schema\SchemaManagerFunctionalTestCase::setUp()`, which skips whenever the concrete subclass does
not support the connected platform. `allowlist.txt` pulls in the whole `tests/Functional/Schema`
directory — the Db2, Oracle, SQL Server, SQLite and (on PostgreSQL) MySQL schema-manager classes —
and they platform-skip. That gate is **driver-independent** and fires identically for stock
`pdo_pgsql`/`pdo_mysql`. **No skip message in any run is driver-gated except one.**

**That one is a real coverage hole, and naming it is the point of this correction:**
`Types\BigIntTypeTest::testUnsignedBigIntOnMySQL` (`tests/Functional/Types/BigIntTypeTest.php:76`)
is the subset's only POSITIVE gate — `if (! isDriverOneOf('mysqli', 'pdo_mysql')) markTestSkipped()`
— so it skips on the MySQL family, where `pdo_mysql` would run it. It is the `BIGINT UNSIGNED`
test, i.e. **the one upstream test that would exercise `TAG_U64` end to end**, and it sits directly
beside the `bigint` read defect triaged below.

The 13 `isDriverOneOf()` call sites in the curated subset (62 in the whole `tests/` tree, which is
where "60 call sites" came from) are: **11 negative gates**
(`if (isDriverOneOf('pdo_oci', 'ibm_db2', 'sqlsrv', 'sqlite3', …)) markTestSkipped()`) that Ferro's
*false* answer makes tests **RUN** rather than skip; **1 assertion** (`ResultTest` asserts
`isDriverOneOf('mysqli','ibm_db2')` is false, which Ferro satisfies); and the 1 positive gate above.
So claiming a driver name would *reduce* coverage everywhere except that single test. Answering
false remains the right choice — but it recovers ONE test, not ~350, and the sentence that said
otherwise pointed readers away from the only place the answer costs anything.

## Every non-passing test, triaged

Categories, as the plan defines them: **(a)** a driver defect to fix now — *none remain*;
**(b)** a documented Ferro semantic; **(c)** an upstream assumption Ferro structurally cannot
satisfy; **(d)** explicitly out of scope for M1. A fifth is added, and the reason is stated rather
than hidden: several failures are **engine gaps this run measured and this slice did not close**.
Calling them (b) would claim they are intended, and calling them (d) would claim they were scoped
out; neither is true. They are **(e)**, and each carries a follow-up.

**One category-(a) driver defect was found and fixed in this task.**
`WriteTest::testLastInsertIdNewConnection` asserts that `getPrevious()` is
`Doctrine\DBAL\Driver\Exception\NoIdentityValue` — the SPI's own signal, which all six bundled
drivers throw. S8b had shipped a Ferro-owned class instead. Nothing in DBAL's `src/` *catches* it, so
the application-visible behaviour was already identical, but there is no reason to invent a second
class for a signal the SPI defines. `Ferro\DBAL\Exception\NoIdentityValue` is deleted and
`Connection::lastInsertId()` now throws the upstream class with the Ferro message verbatim; the guard
is `LastInsertIdLiveTest::testPostgresThrowsAndNamesTheAlternative`, mutation-proven RED by throwing
the sibling `IdentityColumnsNotSupported` instead.

## Not run, and why

- **SQLite:** Ferro has no SQLite backend. Deferred to the milestone that adds
  `ferro-backend-sqlite`.
- **The ORM functional suite:** `doctrine/orm` is not a dependency of this repository and its harness
  has its own driver-injection problem. Deferred; the ORM + PostgreSQL + IDENTITY blocker is recorded
  in `docs/known-incompatibilities.md`.
- **The excluded upstream sub-trees:** see `testkit/dbal/allowlist.txt`, which carries a reason per
  exclusion — the vendor-extension `Driver/*` trees, `Driver/AbstractDriverTestCase` (assumes a
  client-side `dbname`), `LockMode` (cross-connection locking, a later slice), and
  `Ticket`/`Query`/`SQL`/`Platform` (platform-SQL-shape tests, which charter rule 6 says we neither
  own nor change).

## How to reproduce

```bash
FERRO_DBAL_SVC=pg      ./testkit/dbal-suite.sh
FERRO_DBAL_SVC=mysql   ./testkit/dbal-suite.sh
FERRO_DBAL_SVC=mariadb ./testkit/dbal-suite.sh
```

**One variable — CORRECTED.** These commands were three variables each
(`FERRO_DBAL_SVC` + `FERRO_DBAL_POOL` + `FERRO_DBAL_DSN`), and `SVC` (which container is RESET) and
`DSN` (which backend is TESTED) were independent with independent defaults. Dropping one — the slip
a retyped command or a templated CI job makes — reset MariaDB, tested an unreset PostgreSQL, printed
both load-bearing log lines, and produced a THIRD number under the wrong backend's name. The DSN now
defaults from the svc, and an explicitly-set DSN that disagrees is refused before anything is reset.
`FERRO_DBAL_POOL` only names the pool in the log.

**Four lines of every recorded run are load-bearing and must all be present:**

| line | what it proves |
|---|---|
| `[ferro] recordable: yes (whole subset, reset applied)` | no `--filter`/`--group`/path narrowing and no `--no-reset`. **Added because the other three lines are all present and true for a `--filter`ed run that executes 1 test of 730.** Unknown arguments count as narrowing (fail closed) |
| `[ferro] backend: <svc> via <scheme>://<host:port>/<db>` | the container that was reset and the endpoint that was tested are the same backend (credentials stripped, SPEC §12) |
| `[ferro] reset: <svc>/doctrine_tests from …` | idempotence. **Every arm is now fail-closed:** the MySQL-family arms used to swallow every failure (`… \| grep -v 'Using a password' \|\| true`) and print this line anyway, which measured as publishing `Errors 16` under a log claiming the reset ran |
| `[ferro] driver=… platform=… server=…` | the contact assertion passed — a real Ferro connection, not the silent SQLite fallback. Since M1-S8c the bootstrap also asserts the `wrapperClass` |

plus the PHPUnit result line itself, and `[ferro] tree: <sha> · dbal tests: <tag> @ <sha>` for the
manifest. `testkit/dbal-suite-selftest.sh` exercises those guards — including by mutating a copy of
the runner with a broken database password, to prove the reset arm is genuinely fail-closed — and
should be run after any change to the runner.
