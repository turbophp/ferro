## The delta, attributed

**PostgreSQL recovered exactly the 68 tests the S8b triage predicted**: the 50
`int2vector`-blocked schema-manager tests (A2, §22.2 (ae) — the stock PG schema manager, and with
it `doctrine/migrations` and schema diffing, now works through Ferro), the 16 bind-matrix tests
(A3, §22.2 (af)), and the 2 `BigIntTypeTest` errors (A1, m1-s8c). Assertions went 664 → 828 —
the recovered tests genuinely execute their bodies now.

Both MySQL-family gains are exactly the two `Types\BigIntTypeTest::testSelectBigInt` errors
(`9223372036854775806`/`…807`), the S8b category-(e) HIGH-severity client read defect — fixed on
`main` by m1-s8c (ledger A1) and confirmed fixed here by the upstream suite itself.

**Every remaining non-passing test on all three backends is in S8b's (b)/(c) triage — no
category-(a) driver defect and no category-(e) engine gap remains.** PG's 10: 5× `TransactionTest`
(category (b) — the §19.3 fate refinement of `ConnectionLost`, deliberate, charter rule 3), 2×
`WriteTest` lastInsertId (category (b) — PG reports no generated key by design; the documented
ORM-on-PG SEQUENCE consequence, D-S8b-5), 3× `ExceptionTest` credential/host overrides (category
(c) — PHP holds no credentials under Ferro, SPEC §12/D8). The MySQL family's 11 per backend: 5×
`TransactionTest` (b), 3× `ExceptionTest` (c), 2× `MySQLSchemaManagerTest` (c — least-privilege
user, engine-side `dbname`), 1× `PrimaryReadReplicaConnectionTest` charset (c). The ordered
failure sets are byte-identical between MySQL and MariaDB.

## The pg job failure, root-caused (lane defect, not a measurement)

The pg matrix job died in `docker compose up`: *"failed to bind host port for 0.0.0.0:55432 …
address already in use"*. 55432 sits inside Linux's ephemeral port range (32768–60999), so any
transient outbound socket on the runner can be holding it when docker-proxy binds; the
MySQL-family jobs' 33060/33061 sit in the same range and simply got lucky. The lane now reserves
all three ports kernel-side (`net.ipv4.ip_local_reserved_ports`) before `compose up` and retries
the bind once. No suite code changed; the two recorded families above ran before any of this and
are unaffected.

## What this does and does not say about the §14 bar

Unchanged from S8b and restated rather than narrowed: the bar as written ("green on PG + MySQL +
SQLite; ORM suite on PG + MySQL") remains unreachable — **SQLite has no backend** (C3), **the ORM
suite is not run at all** (C-phase), and the measured artifact is the curated
`testkit/dbal/allowlist.txt` subset with driver identity asserted.

**The bar S8b defined for this re-measurement — the subset, real backends, driver identity
asserted, green modulo the triaged list — is now MET on all three shipped backends**:
PG 364/374, MySQL 374/385, MariaDB 373/384, with every non-pass carrying a (b) or (c) triage
entry and reproducing identically across two runs. This is the M1-S9 exit measurement; the
SQLite column and the ORM suite remain the C-phase debts they always were.
