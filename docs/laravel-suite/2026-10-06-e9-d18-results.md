## Not established

- **D18's reading is clause 3, per the §21 open item.** "GREEN modulo triage" means every difference
  from the control is a triaged driver-name artifact or a documented incompatibility (clause 3). It is
  not "green" until the owner settles whether D18 means clause 1.
  *[Settled 2026-10-06 (SPEC §21 D18 as clarified, §22.2 (de)): the owner chose clause 3, and D18's
  text now says only that. A column the gate reports as "GREEN modulo triage" is green. Strict pass
  parity stays reported and is not required. The measurements above are unchanged.]*
- **Strict pass parity is reported, not gated.** It holds on four columns (the three aliases and the
  PostgreSQL-specific directory) and fails on seven; it never fails a job.
- **The ORM workflow (`orm-suite`) has no triage gate.** It was not part of this dispatch.
- **Upstream Laravel's `Sqlite/` directory is not run** — there is no allowlist for it, so the SQLite
  family has no family-specific column, unlike PostgreSQL, MySQL and MariaDB.
- §15's acceptance bar is not restated as met: the `ferro-*` columns are not green under clause 1,
  and the curated allowlist (633 cases) is not upstream's whole integration suite.
- The job logs were read through the GitHub API's job-log endpoint; the uploaded artifacts (JUnit,
  `d18.txt`) were not downloaded from this environment.
